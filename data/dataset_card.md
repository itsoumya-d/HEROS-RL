# HEROS-RL Destructive DDL Migration Set

500 deterministic prompts for training a critic-free GRPO policy to rewrite
hazardous PostgreSQL schema changes as zero-downtime expand-and-contract
migrations.

## Schema

| Field | Type | Description |
|---|---|---|
| `id` | string | Stable case id (`heros-mig-0001`...) |
| `hazard` | string | One of 10 migration families |
| `data_loss` | bool | Whether the target change can lose data |
| `requires_expand_contract` | bool | Whether a multi-phase migration is required |
| `expected_tier` | string | Forge risk tier expected for the target schema |
| `old_schema` | string | Forge Schema Format, `TABLE`/`COLUMN` lines |
| `target_schema` | string | Forge Schema Format, `TABLE`/`COLUMN` lines |
| `prompt` | string | Full instruction with the required tag format |

## Distribution

- 500 cases, 10 families, 50 each.
- 150 data-loss cases, 300 requiring expand-and-contract.
- Tiers: 150 SAFE, 50 NOTABLE, 200 HIGH, 100 CRITICAL.

## Intent

The reward is not learned from human labels. It is deterministic: a strict
`<think>/<answer>` format check, a SQL safety audit that rejects destructive
first steps, and an optional invocation of the HEROS forge binary on the
schema pair. The dataset therefore measures whether a policy can produce a
safe execution plan, not whether it matches one reference string.

Generated by `scripts/build_dataset.py`; reproduced byte-for-byte in CI with
`--check`.
